# Online SEO Portal

## Run locally

Install Node.js 22.13 or newer and MongoDB. On a new checkout, create `.env` from the template and edit it:

```powershell
Copy-Item .env.example .env
```

Then start both separate servers from the project folder:

```sh
npm install
npm run dev
```

Open `http://127.0.0.1:5173`. For separate terminals, run `npm run start:backend` and `npm run start:frontend`. The backend API runs on `http://127.0.0.1:3000`; the frontend obtains its API address from `.env` (`API_BASE_URL`). `npm start` remains available to serve the frontend and API together from port 3000.

Set `MONGODB_URI` to use a different MongoDB deployment, and keep `CORS_ORIGINS` aligned with the frontend origin. The backend waits for MongoDB before accepting requests. To deliver consultation emails, fill in `SMTP_HOST`, `SMTP_USER`, and `SMTP_PASS`. For Gmail, use `smtp.gmail.com`, port `587`, `SMTP_SECURE=false`, and a Google app password. `MAIL_TO` defaults to `info@onlineseoportal.com`; `MAIL_FROM` can be left empty to use the authenticated SMTP user. Never commit `.env` or share SMTP credentials.

The backend separates responsibilities by MVC layer: `backend/models/` contains MongoDB inquiry persistence and the service catalog, `backend/controllers/` handles contact, health, and service responses, `backend/routes/` maps API paths, and `backend/middleware/` parses JSON requests and serves protected static files. Security headers are applied to all responses.

## Consultation API

`POST /api/contact` accepts JSON with `name`, `email`, `service`, and `message`; `phone` is optional. A valid request is saved in MongoDB, then sent to `MAIL_TO` by SMTP as a styled HTML email with a plain-text fallback. If SMTP is not configured or delivery fails, the request remains saved and the API response tells the visitor the email notification did not go out. `GET /api/health` checks MongoDB connectivity, and `GET /api/services` returns the service catalog and consultation choices used by the page.

### MongoDB inquiry schema

Database: `online_seo_portal` (or the database named in `MONGODB_URI`)  
Collection: `inquiries`

```js
{
  _id: ObjectId,          // generated by MongoDB
  name: String,           // required, 1-100 characters
  email: String,          // required, valid email, max 254 characters
  phone: String,          // optional; stored as an empty string when omitted
  service: String,        // required; one of the consultation service choices
  message: String,        // required, 1-2000 characters
  createdAt: Date         // UTC submission time
}
```

Validation is applied in the inquiry model before insertion. SQLite is no longer used for new submissions; any previous `backend/data/leads.sqlite` file is retained and is not automatically migrated.
